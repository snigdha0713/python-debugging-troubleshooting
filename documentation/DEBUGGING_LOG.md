## 2. Bug report

Each confirmed issue will be recorded using this format:

| Field | Details |
|---|---|
| Bug ID | BUG-01, BUG-02, and so on |
| Location | File, function, and relevant line |
| Reproduction steps | Exact input or action that triggers the issue |
| Observed result | What actually happens |
| Expected result | What should happen |
| Error message | Exact message or traceback, if one occurs |
| Root cause | The reason the behaviour occurs |
| Correction | What was changed and why |
| Verification | Test performed and its actual result |

Only issues that can be demonstrated in the supplied code will be included.

## 3. Debugging process

For each issue, the investigation will record:

1. The test input or action used to reproduce it.
2. The observed behaviour and any error output.
3. The hypothesis about the cause.
4. The inspection performed to confirm or reject the hypothesis.
5. The code change made.
6. The test rerun and its result.

Python's `pdb` debugger or an IDE debugger will be used where it helps inspect execution. The log will state which tools were actually used.

## 4. Before-and-after code

A short original code excerpt will be shown beside the corrected excerpt for each relevant bug. Each change will be explained in terms of its effect on program behaviour.

## 5. Code quality improvements

Any refactoring will be listed separately from bug fixes. The purpose of each change and confirmation that intended functionality remains intact will be recorded.
